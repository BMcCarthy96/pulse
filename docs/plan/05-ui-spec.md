# UI Specification

## Design language

Restrained B2B ops tool. This is software an operations team trusts, not a landing page.

- shadcn/ui components, neutral slate palette, `next/font` Inter, dark mode **not** in scope.
- Status colors used consistently everywhere: HEALTHY `emerald`, DEGRADED `amber`, DOWN `red`,
  PAUSED `slate`. One `<StatusBadge status={...}/>` component — never ad-hoc colored spans.
- Vocabulary in UI copy: "Connectors", "Sync History", "Failed Jobs", "Events", "Incidents",
  "Run History", "Audit Log". Never "AI-powered", never marketing adjectives. The AI summary is
  labeled "Draft summary (AI-generated)".
- Timestamps: relative ("4m ago") with absolute on hover/tooltip. Use a single `<Timestamp/>`.
- Every list has: loading skeleton, empty state (with a helpful hint, e.g. "No failed jobs —
  inject chaos from a connector page to see this fill up"), and error state with retry.
- Role gating: hide (don't disable) admin-only controls for non-admins; server enforces anyway.

## Layout

Authenticated shell: left sidebar nav (Overview, Connectors, Jobs, Events, Incidents, Logs,
Settings[admin]) + topbar (org name, global health dot = worst connector status, user menu with
role badge + sign out). Sidebar shows a red count bubble on Jobs (DEAD count) and Incidents
(open count) — data from `/v1/overview`, polled.

## Pages

### `/login`
Email/password form + three "Demo as Admin / Ops / Viewer" buttons (prefill + submit).
Small print: "All data is synthetic. Upstream systems are simulated."

### `/` — Overview
- Row of connector health tiles: name, StatusBadge, error rate (15m), last activity, sparkline
  (24h snapshots), open-incident link if any. Click → connector detail.
- KPI strip: Dead jobs / Open incidents / Events (1h) / Jobs (1h).
- Chart: stacked area or line of error rate per connector over 24h (Recharts, one chart).
- "Recent incidents" table (last 5).

### `/connectors/[key]` — Connector detail (the demo centerpiece)
- Header: name, kind, StatusBadge, paused toggle (admin), "Run sync now" (OPS, poll connectors),
  "Simulate incoming results" (OPS, lab connector), "Submit test claims" (OPS, claims connector),
  "Run eligibility check" (OPS, eligibility connector — small modal form).
- **Chaos panel** (admin only, visually distinct card with a flask icon): current mode, radio
  group of modes, optional failureRate slider for DEGRADED, Apply button → confirmation showing
  the audit consequence. Copy: "Chaos controls the simulated upstream, letting you reproduce
  failure modes on demand."
- Health timeline: 24h status strip (colored segments from snapshots) + error-rate/latency chart.
- Tabs: **Sync History** (runs table: status, trigger, duration, records, error) · **Jobs**
  (recent, filter by status) · **Events** (recent) · **Logs** (recent, level filter).

### `/jobs` — Failed job queue
- Filters: status (default DEAD), connector, queue, time range. Cursor pagination ("Load more").
- Table: job type, connector, attempts `3/5`, last error (truncated), created, finished.
- Row expand or side sheet: payload JSON viewer, full errorHistory as a mini-timeline.
- Row action "Retry" (OPS) + header "Retry all matching" with confirm dialog showing count.

### `/events`
Filters (connector, direction, status) + table (type, direction, StatusBadge for EventStatus,
dedupe key, received/processed). Detail sheet: payload + headers JSON, signature status.

### `/incidents` and `/incidents/[id]`
- List: severity icon, title, connector, status, opened, duration (live for open ones).
- Detail:
  - Header: severity, StatusBadge-like incident status, Acknowledge / Resolve buttons (OPS),
    Add note.
  - **AI summary card**: summary, probable cause, impact, suggested steps (checklist style),
    confidence chip, footer "Generated by {model} · prompt {version} · {time}" + Regenerate
    (OPS) + Edit (opens textarea, saves per API). States: none/queued/generating (spinner),
    failed (error + retry), ready, edited ("edited by {user}" note).
  - Timeline: vertical list of entries (icon per kind), newest last.
  - Context panel: linked connector status, counts of failed jobs/logs in incident window,
    links pre-filtered to `/jobs` and `/logs`.

### `/logs`
Filter bar (level multi-select, connector, free-text `q`, time range) + virtualized-ish table
(level chip, source, connector, message, time). Row expand shows `context` JSON. Live tail =
polling; a "Live" toggle just enables/disables the poll.

### `/settings` (admin)
- **Users**: read-only table (name, email, role).
- **Audit log**: table (time, user, action, target, metadata popover), filter by action.

## Component inventory (build once, in `apps/web/components/`)

`StatusBadge`, `SeverityBadge`, `Timestamp`, `JsonViewer` (collapsible, copy button),
`DataTable` (thin wrapper: columns + cursor pagination + skeleton/empty/error),
`KpiCard`, `Sparkline`, `HealthStrip` (24h colored segments), `ConfirmDialog`,
`PageHeader`, `EmptyState`, `RoleGate` (client helper reading session role).

## E2E demo flow (what Playwright + the Loom both follow)

1. Login as Ops (demo button) → Overview shows all healthy.
2. (As Admin) open EHR connector → chaos panel → set OUTAGE.
3. Trigger "Run sync now" → watch run fail, jobs retry then land in DEAD.
4. Within ~2 health ticks connector shows DOWN; incident appears (sidebar bubble).
5. Open incident → AI summary drafts (or `failed` gracefully without API key in CI).
6. Set chaos back to HEALTHY → retry dead jobs from `/jobs` → they succeed.
7. Health recovers → incident MONITORING → (test can force-resolve via API or shortened window
   config) → RESOLVED.
8. Settings → Audit log shows the chaos change + retries.
